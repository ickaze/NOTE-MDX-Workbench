# 0.11：録音に基づくランダムLFOの等価モデル

本版は0.10bから更新した実験的実装です。定常区間の観測に裏付けられた候補を本体へ組み込みました。全レジスタ操作を実機と一致させるモデルは未完成です。以前の解析報告にある「本体未変更」は、その報告時点の記録であり、本版の状態ではありません。

## 観測から採用までの論証

|観測・検証|判断|実装との対応|
|---|---|---|
|08LONGで初期128点を除く161,318点の二値系列を予測し、不一致0。131,071更新隔てた31,351組も一致|17次の観測系列を採用できる|`sequence_step`、`MeasuredRandom::shift`|
|定常ノイズとランダムAMに同じ系列が現れ、NFRQ変更がAMにも影響する|独立した2個の擬似乱数生成器を廃止し、共有系列とする|`Ym2151::random_`|
|キーオフやLFO停止中にも系列は進行する|LFOが更新される時だけ乱数を進める旧実装は不適切|`advance`で音声・LFO保持と独立に進める|
|NFRQ中間値では平均速度だけのモデルが不一致。16段ごとの更新候補で改善|更新を一様に分散させず、等価的な16段更新を採用|32×(32−NFRQ)マスタークロックごとに16段|
|AM下位ビットは単純な連続8ビット取り出しでは一致しない|ビット別の取り込み時刻を持つB候補を採用|`capture`の4クロック刻みと下位2ビットのずれ|
|PMはAMに対する単純な直線より折り返し変換が良好（07解析：約0.642 Hz RMS、相関0.9997425）|符号折り返し候補を採用|AM<128なら−AM、それ以外は256−AM|

系列の定義は `b[n]=b[n−14] XOR b[n−17]`。右シフトでbit0を出力とするなら、bit0 XOR bit3をbit16へ帰還する形です。この一致は物理回路の全状態が17ビットだけであることの証明ではありません。初期値1は再現可能なソフトウェア上の選択です。

## コードで採用した正確な式

Nを0Fhの下位5ビットとし、D=32×(32−N)マスタークロックとします。系列をDクロックごとに16段進めます。31の場合は32クロックごとの更新になり、64クロックの音声フレームでは2更新が観測されます。ノイズ有効ビットとパンは系列の進行を止めません。

一定Nの区間で、基準時刻からtクロック経過した時のAMビット候補は、j=0..7について

    index[j] = 16 floor((t−4j)/D) −7−j + (j>=6 ? 16 : 0)
    code = b[index[0]] ... b[index[7]]   （MSBから）
    AM = code XOR 255

です。任意の系列初期位相は省略しています。実装では巨大な表を使わず、逆方向にも移動できる17ビット状態から必要なビットを計算します。正方向参照も状態のコピーに対する計算なので、将来の入力を読む処理ではありません。

ランダム値の保持間隔は `2^(24−(18h>>4))` マスタークロックです。4 MHzでは80h=16.384 ms、90h=8.192 ms、A0h=4.096 ms、B0h=2.048 ms、F0h=128 μs（8音声フレーム）。18h再書き込みは保持用カウンタを再開しますが、乱数源は初期化しません。01h bit1による停止中はランダム値と保持用カウンタを保持し、乱数源を動かし続けます。

**18h下位4ビットのランダム取り込みへの影響は未同定です。本版のランダム値保持間隔には反映しません。** 一部の録音に合ったbit反転によるA/B切り替え則は、09〜11の別録音で成立しなかったため採用していません。鋸歯状・矩形・三角波には0.10bの小数カウンタを残しています。最小速度から最大速度まで全設定を実測で確認したという意味ではありません。

## 未確定の遷移と暫定方針

同じNFRQ値の再書き込み32回は連続性を保ちました。一方、値を変えた95境界は単純な状態継承だけでは全てを説明できません。固定17ビットアフィン変換も学習32事例内で不整合となり、検証15事例の完全一致は0でした。

本版は値が変わる時だけ分周カウンタを0に戻し、系列状態を保持します。これは確定した実機仕様ではありません。変更直前4jクロックの履歴も新しい分周器で近似するため、直後の取り込みには追加の不確かさがあります。同じ値の書き込み、ノイズ有効ビットのみの変更ではカウンタを変更しません。波形選択を変えても共有系列を初期化しません。

B候補を固定採用したため、A候補に合う観測条件までは再現しません。AMの整数化、PM端点、電源投入時のシード、01h/18h操作直後の値も未確定です。`uses_unverified_random` は互換性を保ってtrueのままにしています。

## 誤差の意味

12TRANSの境界後95×128=12,160符号は後方定常系列の予測と不一致0でした。境界後34符号だけで位相を求めた独立検証も、続く95×92=8,740符号で不一致0でした。長い過渡状態だけで遷移の不一致を説明する仮説は支持されません。

左右対応の解析では、前半1,672点で共通時刻補正を選び、後半1,647点で減衰量RMS誤差0.118847 dB、MSB不一致0でした。ただし区間ごとのノイズ位相を録音から与え、測定窓の周期を全録音から推定しています。**エミュレータ本体にレジスタ列を入力して得た音声の誤差ではありません。** 区間別補正で得た約0.01 dBも汎用的な再現精度とは扱いません。

解析で得た5.925 μsや0.05 ppmの補正、測定に合わせたdB係数は実機定数と判断せず、ランタイムへ埋め込んでいません。光デジタル録音もSRC後の信号であり、内部値のビット完全な保存とは限りません。

## 再検証資料

`research/recording-analysis.zip` に解析スクリプト、抽出配列、失敗したモデルと数値結果を保存しています。展開先で `python3 lfo-v8/global_clock_fit.py` を実行すると、NumPyを使って上記のAM条件付き予測を再計算できます。元WAVを必要とするスクリプトについては同梱の最終報告を参照してください。

`tests/test_random.cpp` は、生成方法を別にした131,071要素の漸化式配列から14,336組の取り込み期待値を計算し、C++実装を比較します。また161,446点の生成MSB系列の漸化式、保持中の自由進行、時間分割不変性、ノイズ有効ビットの影響を検証します。これらは候補式を正しく実装したかのテストであり、未知の実機遷移が正しいことのテストではありません。
