# 0.11b：測定系列からの推定と軽量化

2026-09-15。17ビットという次数やタップを推定器へ与えず、保存済みの測定振幅・時刻・ノイズ符号列から最短の線形漸化式を求めた。

## 前提を固定しなかった範囲

既に知った情報を人間や解析者から消去することはできない。また入力には過去に抽出した測定値を使っており、生録音から完全に独立した別チームが行う解析ではない。この推定手順の目的は「次数・係数・極性をコードに答えとして与えず、推定手順を再実行可能にする」ことである。

推定器はBerlekamp–Masseyの手順で、二値の線形漸化式の次数を自動的に増やして最短のものを求める。探索対象はGF(2)上の線形漸化式であり、あらゆる非線形プログラムや表引きまで含めた最短プログラムの探索ではない。

08LONGの先頭512観測だけから、中央50%の振幅値の間に255個の判定しきい値候補を作った。各しきい値と両極性で推定し、次数、非ゼロ係数数の順に小さいものを選んだ。保留区間を使って次数やしきい値を修正していない。

## 得られた式

    b[n] = b[n−14] XOR b[n−17]

次数17、非ゼロの遅延項は14と17。従来と同じ式になったが、この推定は17を前提にした適合確認ではなく、次数の推定結果である。

|測定データ|学習|未使用部分の予測|
|---|---|---|
|08LONGのAM二値化系列|先頭512観測|160,934観測、不一致0|
|ノイズ7区間|各区間の先頭512符号|計311,631符号、不一致0|

AMの判定しきい値は学習データだけから11.9192974 dB、極性は小さい減衰量を1とする結果だった。ノイズ各区間からも次数17、遅延14/17が得られた。

予測では保留区間の正解ビットを状態へ戻していない。学習した状態から自走させて比較した。08LONGの保存配列には抽出ブロックの境界で計1,611更新分の欠測がある。時刻列と先頭512点から推定した更新間隔0.00409551150663745秒を使い、その間も状態を進めた。配列の行をすべて連続更新とみなした初期試行は境界から不一致になったため、その扱いを修正した。欠測を乱数規則の例外として補正したわけではない。

この結果は観測された二値系列についてのもの。AM下位ビットの取り込み、NFRQ変更直後の状態、リセット種、PM変換などをすべて確定する検証ではない。

## 実装した計算式

現在の等価モデルは1イベントで系列を16段進める。1段ずつ16回計算する代わりに、推定式を合成した次の式で一度に計算する。

```cpp
constexpr std::uint32_t sequence_advance16(std::uint32_t s) noexcept {
    const std::uint32_t q = s ^ (s >> 3);
    return (s >> 16) ^ (((q << 1) ^ (q << 15)) & 0x1ffffu);
}
```

入力sは現在の17ビット状態。動的メモリ、テーブル、分岐、反復ループを使わない。2つのマスクを使う等価式も比較し、性能がほぼ同じだったため、マスクが1つの式を採用した。1段更新関数はテストや別の段数の参照に残している。

research/inference/derive.pyは、推定された次数・係数から1段更新を組み立て直し、この短縮式との一致を全131,072状態で検証する。次数等が別の結果なら短縮式を無条件に使わず停止する。推定モデルの周期は初期状態へ戻るまで数えて131,071であることを確認した。

## 速度比較

同じC++コンパイラ、-O3、状態依存の連続1,000万イベントを各3回実行した最短時間。単位は16段更新1回あたりns。

|方法|時間|追加テーブル|
|---|---:|---:|
|従来の16回更新|22.5858|なし|
|採用した1マスク直式|1.65657|なし|
|2マスクの等価直式|1.65062|なし|
|状態全体の表引き|5.53827|512 KiB|

2つの直式の差は約0.36%で、測定揺らぎを超えた優劣とは判断しない。採用式は従来の更新に対して約13.6倍だった。これはこの環境のこの更新処理だけの比較であり、エミュレータ全体の倍率、別CPUでの倍率、全方式の中での絶対最速を意味しない。周期表＋位相カウンタなど別の状態表現まで含めて網羅的に比較したものでもない。

## 動作検証

- 全131,072状態で、短縮式と従来の16回更新が一致。
- コア、精度、出力タイミング、測定由来乱数、0.11bの系列更新の5テスト群が通過。
- 既存の乱数取り込み・分周・未確定の状態遷移方針は変更していない。
- 新しい6本のMDXは独立デコードにより待ち時間、レジスタ列、予定表、終端の一致を確認した。実機での再生は未確認。

Visual Studio用ビルドにも新テストを追加したが、この記録の実行確認はLinuxのg++による。CMakeの数値バージョンは0.11.1、表示用バージョンと配布名は0.11b。

## ライセンスと不足する測定

この推定コードと最適化した独自部分には0BSDを適用する。一方、LfoClock、lfo_value、レジスタ処理・深度処理の参照由来部分、および参照比較テストはまだ残っている。この段階の最適化はそこを置き換えたものではないので、パッケージ全体を0BSD単独と表示しない。

## 再実行

プロジェクト直下から：

    python research/inference/infer.py
    python research/inference/derive.py

NumPyが必要。data/には録音から抽出済みの測定配列を同梱している。input_provenance.jsonにハッシュと出典を記載する。これらの配列は正解エミュレータを実行して生成したものではない。

    g++ -std=c++17 -O3 -Iinclude research/inference/benchmark.cpp -o benchmark
    ./benchmark

研究用データの推定結果result.json、式の検証derivation.json、速度benchmark.csvを同梱する。
