# WAV出力の負荷測定（v2.8.8）

WAV出力は実時間を待たずに演算します。Independent OPMでは既存の3段並列パイプライン、Track WAVでは最大4件の並列ジョブを使用します。各トラックのジョブは独立して曲全体を再処理します。ループ回数・曲の長さ・出力トラック数が増えるほど仕事量が増え、同時に再生していればCPU資源も分け合います。X68Soundでは32bitヘルパーとのIPCも加わります。

Linux Release、Independent OPM 0.13と同じC APIのソースを使い、FM音符のみの同一テスト曲（2ループ、28.1659秒、48kHz）を測定しました。Windows DLL実機の速度測定ではありません。

| 処理 | 所要時間 |
|---|---:|
| 通常の直列レンダラー | 1,588.92 ms |
| v2.8.8の並列WAVパイプライン | 1,479.90 ms |
| FMエミュレーションを省いた直列処理 | 130.82 ms |

通常と並列の音声データは完全一致しました。このFMのみのケースでは、FMエミュレーションを含む処理が主な負荷です。ただし、この測定での並列出力は音声の約19倍の速さであり、単純な実時間録音ではありません。実際の曲はFM/PCM構成や発音数、PC性能で結果が変わるため、この数値を全曲や利用者のWindows環境へそのまま適用できません。

進捗表示は各ジョブの生成済み音声時間から算出し、解析済みの曲長・ループ回数・フェード時間を分母にします。待機中のジョブも含めた平均をボタンに描画し、ファイルとループ情報の書き込み完了で100%にします。

この記録は0.13を使用した過去の測定です。v2.9.0以降／0.14のWindows配布DLLについて再測定した値ではありません。
